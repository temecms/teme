# Scale benchmark — 1.6a

> **Provisional (I-154), and not a release run.** 1.6a has no tag; slice 1.6 is measured again, with its search budgets, at the end of 1.6h. This run was made on the shared development machine on 1.5h's fixture, brought forward in place (B-216). Every query-plan rule passed, and check 4 (a fixed number of queries per request) found no deep page costing more than its page one. The machine was busier than for alpha.5: `editor.compare`, which runs no queries, took 553.6 ms against alpha.5's 242.7, and `editor.checkpoint` and *quick edit, draft waiting* ran the same statements as in alpha.5 and took about twice as long. `address.lookup` misses its 2 ms because this host's round trip alone is 2.1 ms (B-218).
>
> **This run's misses are accepted as provisional under I-153 and I-154** (2026-09-25; B-218, B-219). `address.lookup` keeps timing the full round trip; its millisecond verdict comes on 1.13's production-like server (I-154). Until then it is judged by its plan, one index read (an index scan on `paths_path_unique`, 0.088 ms in the database), and its statement count, one per lookup: 2,000 for 2,000 here.
