Teme roadmap · for discussion · 29 October 2026

What comes after phase 1, phase by phase

Every feature placed in a phase, in plain words, and below them every feature that has been raised but sits in no phase yet. Tell me in chat which to move up, down, in or out, by its name or number.

How to read it
  • Each phase ends with a version. 1.0.0, at the end of phase 6, is the first release a stranger can install. Until then Teme runs only on your own servers.
  • A phase also makes a promise to outsiders (the API, the theme interface, the plugin hooks). Moving a feature earlier is easy; moving a promise earlier means changing it later breaks other people's code.
  • Slice lists past phase 1 are estimates. Each phase is planned properly when we reach it, against the code that exists then.
  • ALSO marks a feature already decided for that phase outside its slice list. MAYBE marks one that moves if it proves cheap.

Phase 5 · Plugin API

0.5.0
Done when: someone other than us extends Teme.Promise: the plugin hooks stay stable. This is the one-way door: once outsiders build on it, it can't easily change.
5.1
Hooks
Actions and filters, as in WordPress, where a failing plugin is switched off rather than taking the site down.
5.2
Plugin lifecycle
Install, enable, disable and remove, with a safe mode and a history of what changed.
5.3
What plugins can add
Fields, editor cards, admin screens, AI tools and backup destinations, each labelled with the plugin that added it.
5.3a
Plugin permissions and consent
Each plugin declares what it needs, the administrator agrees, and an update that asks for more is flagged.
5.3b
Plugin screens
The tools for plugins to draw admin screens that match Teme's.
5.3c

Ask from the admin; a separate installer does it, with rollback if it fails.
5.4
Plugin handbook
A guide, a generated hook reference, and an AI skill for converting a WordPress plugin.
I-064

I-3127
Plugins place snippets and their own cardsALSO
A plugin can place snippets automatically, or add its own ad or widget card to the editor.
I-432
Developer kitALSO
Commands that create a working, tested plugin or theme to start from, plus testing helpers.
I-434
FormsMAYBE
Contact and other forms in core, with spam protection and stored submissions. Whether core or a plugin does it is decided in phase 5's study.
I-3167

Plugins' settings pages get the same panels as core's.

Deliberately not building

Each would be a product decision, not a feature to schedule. Raise one if you think it's needed.
—
Multisite
Many sites in one installation.
—
Shared hosting
Teme needs a server with Docker or a VPS.
—
A freeform page builder
Drag-anything layouts, as Elementor does.
—
Ecommerce in core
Shops belong in plugins.
—
WordPress plugin or theme compatibility
Teme imports WordPress sites; it doesn't run WordPress code.
