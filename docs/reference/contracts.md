## Teme\Contracts\Cache

### CacheKeysFor

`Teme\Contracts\Cache\CacheKeysFor`, class. Since 0.1.0.

A change to something the public site shows, as the page cache is told of it: what changed, and the page-cache tags core purges for it, from before the change and after. Core works out which tags a change touches. The tags are the page cache's vocabulary, and a CDN's surrogate keys.

- `CONTENT` — A content item, by its ID. Since 0.1.0.
- `TERM` — A taxonomy term, by its ID. Since 0.1.0.
- `PERSON` — A person the site shows, such as one an item credits, by the ID core gives them: an account's ID for someone with an account, another ID for someone without. Since 0.1.0.
- `MEDIA` — A media item, by its ID. Since 0.1.0.
- `MENU` — A menu, by its handle. Since 0.1.0.
- `SETTINGS` — A settings group, by its key. Since 0.1.0.
- `SITE` — The whole site, as a repair of what every list counts on changes it; its ID is `*`. Since 0.1.0.
- `__construct(string $subject, string $id, array $keys)`. Since 0.1.0.

### PagesPurged

`Teme\Contracts\Cache\PagesPurged`, class. Since next.

The public pages a change purged from the page cache, and the CDN purge queued for them. Sent once for each purge, after the change is saved and never inside its transaction, so a plugin can purge an outside cache of its own. Nothing is sent when the page cache is off. The tags are what a purge is made of, so purge an outside cache by tag. The addresses are only the cached pages core warms again, and are empty when warming is off, so never rely on them being complete.

A hook: its parameters are in the [hooks reference](hooks.md#pagespurged).
