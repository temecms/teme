# Theme reference

> Generated by `php artisan teme:docs:theme` from the code. **Do not edit** — a hand edit here is a bug in the generator.

Every rename, change of type or removal is named in `CHANGELOG.md` under *Theme view data*.

## The manifest

`teme-theme.json`, version 1. Its JSON Schema is `vendor/teme/contracts/schema/teme-theme.schema.json`: point the manifest’s `$schema` at it for an editor’s help.

| Key | Type | Required | Description |
|---|---|---|---|
| `$schema` | string | no | Optional. The path to this file, for an editor's help; Teme reads nothing from it. |
| `manifest` | integer | yes | The manifest's version. Always 1. |
| `code` | string | yes | The theme's code: 2 to 40 lower-case letters, digits and hyphens, starting with a letter or digit. Unique among themes; for a theme in a plain folder, the folder's name. |
| `name` | string | yes | The theme's name, as people see it. |
| `version` | string | yes | The theme's own version. |
| `description` | string | yes | What the theme is for, in a sentence. |
| `requires` | object | yes | What the theme needs. |
| `author` | string | no | Shown to people only; Teme reads nothing from it. |
| `author_url` | string | no | The author’s website. |
| `homepage` | string | no | Where to read about the theme. |
| `license` | string | no | Shown to people only; Teme reads nothing from it. |
| `templates` | object | no | Content type, then template slug, then label. Every slug but default needs views/templates/single-{type}-{slug}.blade.php: only the theme's files can say whether it exists. |
| `navigations` | object | no | The places the theme draws a menu: slot, then label. |
| `regions` | object | no | The places the theme puts the site's own content: slug, then label, group, cards, max, size and minWidth. A region takes every card unless its cards name the ones it takes: Teme's cards by name, a plugin's as code:id. Every core card named must be a registered card: only Teme's registry can say which are. |
| `settings` | array | no | The theme's own settings. A select needs options, and its default is one of them; a boolean's default is true or false; a visible_when names only settings declared before it. |
| `assets` | object | no | The theme's Vite build. |
| `title_separator` | string | no | Between the parts of a page's title; – when absent. |
| `layout` | object | no | The content, wide and full widths in pixels. |
| `images` | object | no | Image context, then its sizes value: lengths in px, vw or rem, every entry but the last after a media condition in parentheses. |
| `fonts` | array | no | The theme's fonts. Core writes an @font-face for each with face true or absent (family, weight, style, src as the same-origin theme file, font-display swap, optional unicode_range) and preloads at most one. face false means preload only — the theme ships its own @font-face. Each file is relative to the theme's public folder and exists there. A theme that writes every face itself may leave this key out, or keep it for preload with face false. |
| `tokens` | object | no | Core design tokens only: base, contrast, accent, on-accent, muted, rule, brand, font-body, font-heading, font-mono, step--1 to step-5, space-1 to space-8. Each value is CSS with no ; { } < or >. base and accent are hex colours. brand is read-only: core writes it from the site's brand colour. For a theme's own names, use custom_tokens. |
| `tokens_dark` | object | no | The same core tokens and rules, for the theme's dark scheme. brand is read-only. |
| `custom_tokens` | object | no | The theme's own design tokens beyond the core list, written as --teme-<name> after the core tokens. Names are lower-case letters, digits and hyphens, starting with a letter, and must not equal a core token. Values follow the same rule as tokens. |
| `custom_tokens_dark` | object | no | The theme's own dark-scheme tokens, same name and value rules as custom_tokens. |
| `styles` | object | no | Named looks the theme can switch between. Core adds a Style select (fieldset site), defaulting to the first style. Each style may set tokens, tokens_dark, custom_tokens, and fonts (one declared font file to preload). Document and design previews use the chosen style over the base tokens and preload. |
| `speculation` | boolean | no | A theme may only opt out: false leaves the prerendering rules out. |
| `breadcrumbs` | boolean | no | Whether the theme draws a breadcrumb trail; false when absent. |
| `screenshot` | string | no | A path inside the theme, with no .., to a .png, .jpg or .webp image, in any case. A missing file is no error. |
| `icon` | string | no | The theme’s icon: a path inside the theme, with no .., to a .png, .jpg, .jpeg, .webp or .svg picture, in any case. Square; drawn at up to 96 pixels. A missing file is no error. |
| `screenshots` | array | no | Up to 8 pictures of the theme at work, in the order Teme’s directory shows them. |
| `cards` | object | no | Cards the theme styles itself, and cards it brings for its own regions. |
| `composers` | array | no | Class names of the theme's view composers, each asking only for Teme\Contracts interfaces. |
| `per_page` | integer | no | Items per page of a listing; 10 when absent. |
| `csp` | object | no | Outside hosts the theme's pages load from, by kind. Each is a host name or *.host; https is implied. A theme's own files are always allowed. |

## Kinds of page

| Kind | `$page` | Templates tried, in order |
|---|---|---|
| `latest` | `LatestView` | `latest` |
| `single` | `ArticleView` | `single-post-full-width`, `single-post`, `single` |
| `archive` | `ListingView` | `archive-post`, `archive` |
| `taxonomy` | `ListingView` | `taxonomy-category-news`, `taxonomy-category`, `archive` |
| `author` | `ListingView` | `author`, `archive` |
| `search` | `ListingView` | `search`, `archive` |
| `date` | `ListingView` | `date`, `archive` |
| `notfound` | `NotFoundView` | `notfound` |
| `error` | `ErrorView` | `error-404`, `error` |
| `comments` | `CommentsPageView` | `comments` |
| `respond` | `RespondView` | `respond` |
| `protected` | `ProtectedView` | `protected` |

`index` is the floor every kind but `error` falls to. An `error` falls to core’s own error page; `comments`, `respond` and `protected` fall to core’s own page. A theme names no list of the types or taxonomies it draws: a file named for one draws it, and `single` and `archive` draw the rest.

## What every template gets

| Name | Type | Description |
|---|---|---|
| `$page` | `LatestView\|ArticleView\|ListingView\|NotFoundView\|ErrorView\|CommentsPageView\|RespondView\|ProtectedView` | The page being drawn: its model is the one its kind of page names. |
| `$site` | `SiteView` | The site: its name, tagline, home address, language and the current year. |
| `$teme` | `array{version: string, release: string}` | The version of Teme the site runs, such as 1.2.0, and its release, such as 1.2: a pre-release such as 1.2.0-rc.1 is release 1.2. An untagged build gives both as UNTAGGED. |
| `$navigation` | `array<string, list<array{label: string, url: string\|null, current: bool, opensNewTab: bool, heading: bool, children: list<mixed>}>\|null>` | Each of the theme's navigation slots with its menu's tree, or null when it has none. |
| `$themeSettings` | `array<string, mixed>` | The active theme's own settings, key to value, without its menu places. |
| `$isFront` | `bool` | True only on the site's home page and its numbered pages. |
| `$language` | `PageLanguageView` | The language of the page being drawn: its tag, its own name and its home address. |
| `$direction` | `string` | The direction of the page's language: ltr, or rtl for a language written right to left. |
| `$alternates` | `list<Alternate>` | Every language version of this page a reader can open, this page included, the default language first; empty when there is only this page. |

Laravel’s own `$errors`, `$attributes` and `$slot` are Blade’s, not Teme’s, and may change with Laravel.

Core may add `language`, `direction` and `alternates` to a page’s data; a theme’s composer must not return them.

A theme never writes `dir` or `lang`: the page’s shell does. Use logical CSS properties (start and end, not left and right).

## The page’s values

| `$authors` | `list<Person>` | The people the item credits, its bylines, in order, the main one first; none when it credits no one. A person need not have an account here. |
| `$published` | `DateTimeImmutable` | In the site's time zone. |
| `$updated` | `?DateTimeImmutable` | Only when the revision shown is at least a day newer than the first publication. |
| `$publishedText` | `string` | The publication date as words, in the item's language. |

| `$lead` | `?ImageRef` | The lead image, or null when there is none. |

| `$related` | `list<array{item: ListingItem, reason: string}>` | Up to three related posts, each with the reason it is shown; empty when nothing is shared. |

| `$revisionId` | `string` | The revision shown: the published one, or the one a preview shares. |

| `$parent` | `?ItemLink` | the item it sits under, while readers can see it; null at the top, for a type that doesn't nest, and while its parent is hidden |
| `$ancestors` | `list<ItemLink>` | the items above it that readers can see, the top first; the trail is made from them |
| `$children` | `list<ItemLink>` | the published items under it, in their order, at most 100 |
| `$siblings` | `list<ItemLink>` | The published items of its type under the same parent, itself among them, in menu order, at most 100. Top-level pages are siblings of each other. None for a type that doesn't nest. Read from the database the first time a template asks, never otherwise. |
| `$previous` | `?ItemLink` | The sibling before it in menu order; null for the first, and for a type that doesn't nest. Read when a template asks. |
| `$next` | `?ItemLink` | The sibling after it in menu order; null for the last, and for a type that doesn't nest. Read when a template asks. |
| `$blocks` | `list<Block>` | The body's top-level blocks in order, each its type, attributes and HTML, drawn by the renderer `bodyHtml` is drawn by; plugin insertions are not among them. Drawn the first time a template asks, never otherwise. |
| `withUrl()` | `(string $url): self` | The same article at another address. |
| `field()` | `(string $handle): ?FieldView` | One of this type's fields by its handle, as a FieldView that prints as its text, with the type's default when nothing is stored; null for a handle the type doesn't have, because one template may serve several types. |
| `shownFields()` | `(?string $where): list<FieldView>` | The fields to list `after` or `before` the article, or with no place both, in order: those the site set to show there that hold something. |

| Name | Type | Description |
|---|---|---|
| `$count` | `int` | approved comments, pings included |
| `$open` | `bool` | whether it takes new comments now: Open, and within the days the settings allow |
| `$current` | `int` | this page's number |
| `$total` | `int` | how many pages the thread has, at least 1 |
| `$depth` | `int` | how deep replies go (thread_depth), for core's script |
| `$items` | `list<CommentView>` | this page's conversations, oldest first, each with its replies |
| `$pagination` | `Pagination` | previous is the older page, next the newer; page 1 is the item at #comments |

## Components

### `<x-teme::between-items>`

`<x-teme::between-items :after="$loop->iteration" :last="$loop->last" />`: what plugins place between a list's items, after this item, cleaned; nothing after the last item, or where nothing is placed. A theme puts it inside its list loops.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `after` | `int` | — | the item just drawn, counted from 1 |
| `last` | `bool` | false | whether it is the list's last item |

### `<x-teme::comment-form>`

`<x-teme::comment-form>`: core's comment form, which a theme places and styles. Where only signed-in people may comment, a browser that carries no sign-in marker, whose page may be stored and shared, gets a line in its place.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `form` | `CommentFormView` | — | what the form is drawn with |

### `<x-teme::document>`

`<x-teme::document>`: core's document shell around every public page, so a template writes only its own markup. It writes the `lang` and `dir`, the colour scheme, the title, the head's typed entries (DocumentMeta, the robots value among them), the one preloaded font, `@font-face` rules from the manifest's fonts, the theme's tokens and its dark ones, with the site's accent, lightened for the dark scheme, the theme's assets, the styles of the cards the page drew, the page's JSON-LD graph, the three placements, with their fragments, the skip link and its style, the speculation rules, and core's small script, which in a browser that signed in asks who is reading and adds the "Edit" link. It reads the page from ComposerRegistry, where PublicPage started it, never the template's variables.

No attributes.

### `<x-teme::image>`

`<x-teme::image>`: a theme's way to draw a media item, such as `<x-teme::image :id="$page->lead->id" context="feature" :priority="true" />`. It is thin: ImageMarkup writes the `<img>`, so every image on the site, cards included, comes out the same.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `id` | `string` | — | the media item's ID |
| `context` | `string` | 'content' | the image context the theme's manifest gives a sizes value for, such as feature |
| `priority` | `bool` | false | whether the image is the page's most important, loaded first |
| `alt` | `?string` | null | the alt text for this use; null for the media item's own |
| `decorative` | `bool` | false | whether the image is decoration, drawn with empty alt text |

### `<x-teme::inline-script>`

`<x-teme::inline-script>`: one of core's own inline scripts, written exactly as its hash is noted in the page's policy, so the page stays shared and a policy allows it without a nonce. Core's alone: a theme's scripts go in its build, which teme:theme:check holds it to.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `name` | `string` | '' | the script's data-teme marker, by which core's tests and scripts find it |
| `type` | `string` | '' | the script's type, such as speculationrules; none for a classic script |

### `<x-teme::items>`

`<x-teme::items type="docs" :limit="20" />`: a public type's published items in the page's language, newest first or in menu order, at most 100. With `partial="partials.doc-list"` the theme's own partial draws them, given `$items`; without it a plain list of links is drawn. Nothing for a type that is unknown or not public.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `type` | `string` | — | the type's key |
| `limit` | `int` | 10 | how many items, from 1 to 100 |
| `order` | `string` | 'newest' | `newest` (the default) or `menu` for the order a hierarchical type's items are arranged in |
| `partial` | `?string` | null | the theme's own view to draw them with, such as `partials.doc-list` |

### `<x-teme::languages>`

`<x-teme::languages />`: a link to each language version of the page, for a theme that places its own switcher. The same links as a menu's language switcher, in a plain list with `lang` and `hreflang` on each and `aria-current` on the page's own; nothing on a page with no other version.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `showNames` | `bool` | true | whether each link reads its language's own name, such as Français, rather than its short code, such as FR |
| `hideCurrent` | `bool` | false | whether the page's own language is left out |

### `<x-teme::navigation>`

`<x-teme::navigation slot="primary" label="Main" />`: the menu a theme's slot shows, as a labelled landmark with `aria-current` on the page being shown. A slot with no menu is loud outside production and silent in it. It reads the slot from SlotMenus, never the template's variables. Its view gets the slot as `$slotKey`: there, `$slot` is always Blade's default slot. A heading is drawn as a button that opens the list of its items.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `slot` | `string` | — | the theme's navigation slot to draw, such as primary |
| `label` | `?string` | null | the landmark's name for screen readers; the slot's label when null |

### `<x-teme::password-form>`

`<x-teme::password-form>`: core's form for an item protected by a password, which a theme places and styles.

| Attribute | Type | Default | Description |
|---|---|---|---|
| `page` | `ProtectedView` | — | the protected item's page |

### `<x-teme::region>`

`<x-teme::region name="after-content" />`: the site's own content a theme places, such as a newsletter box after the article, drawn from the region's published revision, its cards recorded for the page's head. Nothing for a region that's empty or unpublished; outside production, a note for a name the theme's manifest doesn't declare. ### `<x-teme::thread-script>`

`<x-teme::thread-script>`: core's comments script, pushed once onto the shell's stack. The comment form uses it, and a theme that draws a thread with no form, a closed one, places it where it draws one, so a moderator's Edit links reach it.

No attributes.
